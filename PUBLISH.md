## Publish to PyPI

Official guide: [Packaging Python Projects](https://packaging.python.org/tutorials/packaging-projects/)

---

## Recommended workflow (publish.sh)

Publishing is normally handled by the `publish.sh` script, which automates the full release process.

```bash
export PYPI_API_REPOSITORY_PROD='https://upload.pypi.org/legacy/'
export PYPI_API_TOKEN_PROD='<YOUR_PROD_TOKEN>'
export PYPI_API_REPOSITORY_TEST='https://test.pypi.org/legacy/'
export PYPI_API_TOKEN_TEST='<YOUR_TEST_TOKEN>'

export EFFECTIVE_BRANCH=develop
export RUN_NUMBER=1

bash ./publish.sh
```

The script automatically performs the following steps:

- Determines the correct **PyPI repository** (Test or Production)
- Calculates the **package version**
- Installs / upgrades required **build tools**
- Cleans previous build artifacts
- Builds the **sdist and wheel**
- Uploads the package to PyPI

In most cases, this script is the only command you need to run.

---

## Manual publishing steps (for reference)

The following describes the steps performed internally by `publish.sh`.  
These are useful for debugging or manual publishing.

---

### Update version

Version is **dynamically managed** via `car_framework.__version__` defined in `__init__.py`.

Locally, you can override it by setting the environment variable:

```bash
export PYPI_PACKAGE_VERSION=4.0.3
```

Otherwise, `publish.sh` determines the version automatically based on Git tags/branches:

- Tag matching `vX.Y.Z` → final release
- Otherwise → `latest_tag-rc.<RUN_NUMBER>` for release candidates (RC)

---

### Install / upgrade build tools

```bash
python3 -m pip install --user --upgrade pip setuptools wheel build twine keyring
```

> `keyring` is optional but recommended for token-based uploads.  
> `build` is used to run isolated PEP 517 builds instead of `setup.py`  
> (migrated to PEP 517 builds as of `v4.0.3`).

---

### Clean previous builds

```bash
rm -rf ./build ./dist ./car_connector_framework.egg-info
```

---

### Build the distribution

```bash
python3 -m build
```

This uses `pyproject.toml` and the PEP 517 build backend to produce:

- **sdist**
- **wheel**

Both are placed in the `dist/` directory.

---

### Upload to PyPI

Manual upload example:

```bash
python3 -m twine upload -u "__token__" -p "<TOKEN>" --repository testpypi dist/*
```

When using `publish.sh`, the script automatically determines whether to upload to:

- **Test PyPI**
- **Production PyPI**

based on the branch or tag being built.

---

### Test the published package

```bash
pip install -i https://test.pypi.org/simple/ car-connector-framework==<VERSION>
```

Replace `<VERSION>` with the version produced during publishing.

---

## Notes / Tips

- `python -m build` replaces the old `setup.py` workflow and uses **PEP 517 isolated builds**.
- Versioning is **Git-aware** and does not require manual edits.
- `.egg-info` directories are generated by `setuptools` during builds and can be safely deleted before rebuilding.
- Always keep `twine` and `keyring` up to date.
- Release candidates (`rc`) are safe for testing; final releases should be created from **version tags**.
